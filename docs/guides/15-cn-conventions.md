# 中文本地化约定：数字单位、日期轴、中国式报表表格

国内 BI 交付物有三件事几乎一定会被追问：数能不能按「万 / 亿」读、日期能不能写成「3月1日」、明细表能不能带序号和合计。这篇把 1.2.0 里对应的三组能力放在一起讲，照着改就能让图表更像帆软 / 观远那类报表。

> 所有示例都可直接运行：先 `import eazy_data_viz as edv`，`df = edv.sample_df()`；需要写文件时统一输出到 `examples/output/`。

## 1. 数字：万 / 亿 / 百万

### 1.1 默认就会缩略

不传任何参数时，数值走内置的中文缩略规则（`compactCN`）：≥1 亿用「亿」、≥1 万用「万」，缩略后的数小于 100 保留 1 位小数，≥100 取整；缩略出来的数不加千分位，整数不带 `.0`。

| 原始值 | 默认显示 | 说明 |
| --- | --- | --- |
| `9,876` | `9,876` | 不足 1 万，走千分位 |
| `10,000` | `1万` | 末尾的 `.0` 去掉 |
| `12,345` | `1.2万` | 缩略后 <100，保留 1 位小数 |
| `123,456` | `12.3万` | 同上 |
| `12,345,678` | `1235万` | 缩略后 ≥100，取整且不加千分位 |
| `150,000,000` | `1.5亿` | ≥1 亿 |

### 1.2 用 `.unit()` 强制一个单位

默认缩略是按每个数各自判断的，同一张图里可能出现「1.2万」和「1235万」混排。要统一读数，用链式的 `Chart.unit(unit)`：

| 写法 | 倍数 | 原值 `16,456,600` 显示为 |
| --- | --- | --- |
| `.unit("千")` | `1e3` | `16456.6千` |
| `.unit("万")` | `1e4` | `1645.66万` |
| `.unit("百万")` | `1e6` | `16.46百万` |
| `.unit("亿")` | `1e8` | `0.16亿` |
| `.unit(1e4)` | `1e4` | `1645.66万`（数字与 `"万"` 等价） |
| `.unit("1e6")` | `1e6` | `16.46百万`（也接受这种字符串） |

规则是「值 ÷ 单位基数」，**最多保留 2 位小数**并去掉末尾的 0，后面拼单位字。作用范围是整张图：坐标轴刻度、tooltip、数据标签、饼图/漏斗/仪表盘读数、KPI 卡片、明细表单元格。

```python
import eazy_data_viz as edv

df = edv.sample_df()

# 一张图里所有销售额读数统一成「万」
edv.bar(df, x="大区", y="销售额").unit("万").save("examples/output/cn_unit_bar.html")

# 饼图 / 漏斗 / 仪表盘 / KPI 同样吃 unit
edv.pie(df, names="渠道", values="销售额").unit("万").save("examples/output/cn_unit_pie.html")

# 数字倍数与中文字符串等价
edv.line(df, x="月份", y="利润").unit(1e4).save("examples/output/cn_unit_line.html")
```

### 1.3 单位要跟数据量级匹配（不做自动降级）

`unit()` 是「强制单位」，不会因为数值太小就自动换成更小的单位。单位选得比数据量级大，就会出现 `0.16万` 这种读数：

```python
# 1548.09 用「万」→ 0.15万：单位选大了，读数反而不好看
one = df.head(1)[["产品", "销售额"]]
edv.bar(one, x="产品", y="销售额").unit("万")
```

经验法则：先看数据的量级，再选一个让读数落在 **1 ~ 9999** 之间的单位。1e6 量级建议用「万」读成 `100万`，而不是用「百万」读成 `1百万`——后者虽然没错，但不符合中文报表的阅读习惯。

### 1.4 与 `fmt` 的优先级

`unit` 和 `fmt` 同时存在时，`fmt` 优先，避免双重换算：

| `fmt` | `unit` 是否生效 | 说明 |
| --- | --- | --- |
| `compact`（默认） | ✓ | 按 `unit` 换算；没设 `unit` 时走 1.1 的默认缩略 |
| `raw` | — | 原样输出，`unit` 被忽略 |
| `percent` | — | `12.3%`，`unit` 被忽略 |
| `thousands` | — | 千分位，`unit` 被忽略 |
| `currency` | — | `¥1,234.56`，`unit` 被忽略 |
| `thousands` + `table` | ✓ | **表格例外**：表格的 `fmt="thousands"` 仍按单位换算，否则表里看不出「万 / 亿」 |

单位只接受 `"千"` / `"万"` / `"百万"` / `"亿"` 或 `1e3` / `1e4` / `1e6` / `1e8`（含 `"1e6"` 字符串）。`"万元"`、`"℃"`、`"%"` 这类**纯文字单位会被拒绝**——它们不是数量级，请用图表函数自带的 `subtitle` 或 `fmt` 表达：

```python
try:
    edv.bar(df, x="大区", y="销售额").unit("万元")
except ValueError as exc:
    print("纯文字单位会被拒绝：", exc)
```

```text
纯文字单位会被拒绝： unit='万元' 不支持，可选：千 / 万 / 百万 / 亿，或 1e3 / 1e4 / 1e6 / 1e8
```

## 2. 日期：把 2024-03-01 显示成 3月1日

类目轴（x 或 y 是类目轴）上的字符串如果长得像日期，会自动改成中文写法。**只改坐标轴显示**：类目原始值、tooltip 表头、导出与下钻用的都是原始完整日期。

| 输入（同一轴上的类目） | 轴上的显示 | 条件 |
| --- | --- | --- |
| `2024-03-01` | `3月1日` | 整条轴都是同一年 |
| `2024-03-01` / `2025-01-15` | `2024年3月1日` / `2025年1月15日` | 轴上有多个年份，补上年份 |
| `2024-01` | `1月` | 只有年月 |
| `2024-03-01 09:30` | `3月1日 09:30` | 带时间，时间原样保留 |
| `2024/03/01` | `3月1日` | 斜杠分隔同样识别 |
| `2024-03-01 09:30:15` | `3月1日 09:30` | 秒会被去掉（轴只显示到分钟） |

支持 `YYYY-MM-DD`、`YYYY/MM/DD`、`YYYY-MM`、`YYYY/MM`，以及带 `HH:MM` / `HH:MM:SS` 的 ISO 形式（日期与时间之间用空格或 `T`）。生效有两个前提：

1. 该轴是**类目轴**，且类目是字符串；
2. **整条轴都能解析、且粒度一致**（全是「日」或全是「月」）。混用 `2024-03-01` 和 `2024-03` 时整条轴保持原样，不做部分替换。

```python
import pandas as pd
import eazy_data_viz as edv

df = pd.DataFrame({
    "日期": ["2024-03-01", "2024-03-02", "2024-03-03", "2024-03-04"],
    "销售额": [1200, 1350, 980, 1600],
})

# 横轴显示 3月1日、3月2日……；tooltip 表头仍是 2024-03-01
edv.line(df, x="日期", y="销售额").save("examples/output/cn_date.html")

# 跨年：显示 2023年12月30日、2024年1月2日
df2 = pd.DataFrame({
    "日期": ["2023-12-30", "2024-01-02", "2024-02-15"],
    "销售额": [900, 1100, 1300],
})
edv.line(df2, x="日期", y="销售额").save("examples/output/cn_date_cross_year.html")
```

已经是中文的类目（`1月`、`2024年1月`）不会被二次加工，可以放心和默认缩略混用。刻度旋转角度按**格式化后的中文文本**宽度计算，不会因为「3月1日」比「2024-03-01」短就把标签挤在一起。

## 3. 表格：中国式报表

`table()` 在 1.2.0 增加了 4 个参数，参考帆软 FineReport 明细表与观远 BI 表格：

| 参数 | 类型 | 默认 | 作用 |
| --- | --- | --- | --- |
| `total` | `bool` | `False` | 表尾「合计」行，只统计 `limit` 内实际渲染的行 |
| `index` | `bool` | `False` | 最左侧「序号」列（1..N），横向滚动时固定 |
| `bar` | `bool / str / list[str] / None` | `None` | 单元格数据条：`True` 取第一个数值列，也可指定一列或多列 |
| `stripe` | `bool` | `True` | 斑马纹，1.2.0 起默认开启 |

组合起来就是一张可以直接交付的明细表：

```python
import eazy_data_viz as edv

df = edv.sample_df()
chart = edv.table(
    df,
    columns=["大区", "产品", "销售额", "利润"],
    limit=12,
    index=True,        # 序号列
    total=True,        # 表尾合计
    bar="销售额",      # 销售额画数据条
    title="重点明细（含合计）",
    subtitle="合计只统计当前显示的 12 行",
)
chart.save("examples/output/cn_table.html")
```

几个容易忽略的默认样式（不用额外参数）：

* **表头 sticky**：纵向滚动时表头不跑。
* **首列固定**：横向滚动时第一列（开了 `index` 就是序号列）钉在左侧。
* **合计行**：4px 双线 + 浅底色 + 加粗，数值按单元格同样的 `fmt` 显示（如 `7,735.98`）。
* **空值**：统一显示「−」，不会出现 `None` / `null` / 空白。
* **数据条**：条宽 = `|值| / 该列绝对值最大`；浅色主题 alpha 0.22、深色 0.34；多列时按主题调色板依次取色。

没有 `index` 时「合计」标签占第一列；如果第一列本身就是数值列（只选了几列数值做透视表），
「合计」会跟这一列的合计挤在同一格（如 `合计 6,044.28`），所以这一列的合计不会丢。

注意 `bar` 指定的列必须同时出现在 `columns` 里，而且必须是数值列；`total` 只算 `limit` 内实际渲染的行，和底部「共 N 行，仅显示前 M 行」一致。参数细节与报错文案见 [table API](../api/table.md)。

## 4. 限制与坑

* **扩展图的 tooltip 不吃 `unit`**：`eazy_data_viz/assets/eazy_extra_a.js` 与 `eazy_extra_b.js` 里那些在 hover 时才执行 tooltip 闭包的扩展图，`unit` 对它们的 tooltip / label 不生效；核心图（`bar` / `line` / `pie` / `funnel` / `gauge` / `kpi` / `table` / `histogram` / `heatmap` / `scatter` / `box` / `treemap`）以及所有坐标轴都正常。
* **`unit` 不做自动降级**：强制单位后，数值再小也按该单位显示（`0.16万`）。单位要跟数据量级匹配，见 1.3。
* **`fmt` 优先**：`fmt` 为 `raw` / `percent` / `thousands` / `currency` 时 `unit` 不生效，只有表格的 `thousands` 例外。
* **`stripe` 默认开启**：1.2.0 起旧图会多一层很浅的斑马纹；要还原旧观感传 `stripe=False`。
* **Streamlit v2 默认不 rerun**：1.3.0 起，不传 `on_select` 时点击、联动、下钻全部在浏览器内完成，零次脚本 rerun（`result.select` 恒为 `None`）；传了 `on_select` 才会回传一次。1.2.0 修复的是「图表 id 每次 rerun 漂移导致整块重挂、状态清零」，现在 id 稳定（1.4.0 起形如 `eazy-<看板指纹>-<位置>`）、状态保留。完整说明见 [07 · Streamlit 集成](07-streamlit.md) 的「点击图表会不会 rerun？（v2 必读）」。
